## 4. Layouts and partials

The audit script's layout, asset and JS sections came back empty: they scan the project `layouts/` only, and every template lives in the module cache. Scanned the module by hand:

- Base: theme `baseof.html`, `docs/baseof.html`, `blog/baseof.html` — navbar, footer, scripts partials; docs/blog add sidebar, TOC, breadcrumb.
- Page templates: `all.html` = `.Content`; `_td-content.html` and `blog/_td-content.html` render `<h1>{{ .Title }}</h1>`, `.lead` description (markdownify), byline, `.Content`.
- Shared partials: `navbar.html` (logo via `resources.Get "icons/logo.svg"`, `site.Menus.main`, **`.HasShortcode "blocks/cover"` decides the translucent navbar**), `footer.html` → `footer/left|right|center` reading `site.Params.links.user|developer`, `site.Params.copyright`, `site.Params.privacy_policy`.
- `community_links.html` reads `site.Params.links` and i18n strings.
- Shortcodes used in content: `pageinfo` (9), `alert` (5), `imgproc` (1), `blocks/*` (home/about), `_param`/`param` (config-value interpolation), `td/site-build-info/netlify` (1). The theme also offers `tabpane`/`tab`, `cardpane`/`card`, `iframe`, `readfile`, `swaggerui`, `redoc`, `conditional-text`, `comment` — not used in the example content.
- Asset pipeline: `blocks/cover` (`.Fill` on page resource `**background*`, `.Fit` on `**logo*`, inline `<style>` + `<link rel=preload>`), `imgproc` (`.Fit/.Resize/.Fill/.Crop`), `featured-image.html` (`.Fill`), navbar logo, CSS/JS bundles in head/scripts (page templates, not re-rendered).
- Images: page bundle resources (`content/featured-background.jpg`, `about/featured-background.jpg`, blog post image). `static/` only has favicons.
- `.Content` in partials: only `print/*` (not relevant) and `navbar.html` (minified SVG `.Content`, not page content).

## 5. Build pipeline

- `npm run build` → `hugo --cleanDestinationDir -e dev --logLevel info -DFE` (dev environment, drafts/future/expired!). Production is `build:production` → `hugo --cleanDestinationDir --minify`. CloudCannon should use production.
- Needs `npm ci` first (Bootstrap/FA/Sass). Dart Sass is found via `node_modules/.bin` on PATH; `npm run` provides that.
- `enableGitInfo: true` (needs git history at build time).
- No postbuild steps; no Pagefind. Search: Google CSE (`gcs_engine_id`) — keep or switch to `offlineSearch: true` (Lunr, no external service) for a starter.
- `security.funcs.getenv` allows Netlify env vars only.

## 6. Flags and special patterns

- **Positional selectors**: to check in Docsy SCSS during Phase 4 for `.td-box`, `.row > *`, `.col-lg-4` feature items.
- **Global JS**: `assets/js/base.js`, `chrome-nav.js` (navbar translucency `js-td-cover`, shared-chrome donor fetch), `scrollspy-patch.js`, `click-to-copy.js`, `dark-mode.js` — bind at load. Re-rendered cover blocks may lose the navbar-translucency hook.
- **Inline `<style>` in `blocks/cover`** — per-instance style keyed by `.Ordinal`; must be reworked in the partial (inline `style=` attribute instead).
- **`.HasShortcode "blocks/cover"`** in navbar — converting cover to a content block silently drops the transparent navbar. Needs a navbar override (check `content_blocks` for a cover block).
- **Numbers as text**: none.
- **Raw HTML in content**: yes (home CTA buttons, site badge). Goldmark `unsafe: true`, `parser.attribute.block: true` (`{.display-6}` attribute syntax).
- **Scroll-reveal**: none.
- **Existing CMS/deploy config**: Netlify (removed in scaffold); `_redirects` output format (Netlify-specific, harmless).
- **Shared chrome** (`chrome-render.html`) — optional mode that drops footer and fetches it client-side; off by default.
